# Chezmoi source state

Files here are desired configuration, not live files. `chezmoi apply` renders them into the
home directory. The repository-root `.chezmoiroot` file makes this directory the top of the
source state; it does not create a `~/home/` directory.

For example, `home/dot_bashrc` renders to `~/.bashrc`. This `.README.md` starts with a dot,
so chezmoi ignores it and never deploys it.

## Directory map

| Source | Target or role |
| --- | --- |
| `.chezmoitemplates/` | Shared bodies; never deployed directly |
| `dot_agents/` | Shared skills under `~/.agents/` |
| `dot_claude/` | Claude Code configuration under `~/.claude/` |
| `dot_codex/` | Codex configuration under `~/.codex/` |
| `dot_copilot/` | GitHub Copilot configuration under `~/.copilot/` |
| `AppData/`, `Library/` | Windows and macOS VS Code user-profile targets |
| `dot_bashrc`, `dot_zshrc.tmpl`, `dot_bash_profile` | Shell configuration |

Source filename prefixes carry chezmoi attributes. Do not rename or add files here until you
understand how `dot_`, `create_`, `empty_`, `literal_`, `symlink_`, and `.tmpl` affect the
target.

Read [the chezmoi workflow](../docs/chezmoi-workflow.md) before editing. For instructions,
skills, agents, prompts, MCP servers, or plugins, also read the
[AI customization guide](../docs/customization-support.md).
