# This directory is the chezmoi source state

Files here are **not** live configuration. `chezmoi apply` renders them into your home
directory. This file starts with a dot, so chezmoi ignores it — it is repository
documentation only and is never deployed.

The repository-root `.chezmoiroot` file contains `home`, which makes this directory the top
of the source state. Chezmoi does not create a `~/home/` directory. For example,
`home/dot_bashrc` renders to `~/.bashrc`.

Full guide: [../docs/chezmoi-workflow.md](../docs/chezmoi-workflow.md)

## Reading the folder names

`dot_` becomes a leading dot in the target, so `dot_claude/` → `~/.claude/`. That means the
folder list below looks like four tools, but **one of them is the shared tree**:

| Folder | Target | Role |
| --- | --- | --- |
| `.chezmoitemplates/` | *(never deployed)* | **SHARED bodies.** Rule and core text, written once |
| `dot_agents/` | `~/.agents/` | **SHARED skills.** Codex and Copilot read this path natively; Claude reaches each skill through a symlink |
| `dot_claude/` | `~/.claude/` | Claude Code only |
| `dot_codex/` | `~/.codex/` | Codex instructions, agents, Model Context Protocol (MCP), and plugin defaults |
| `dot_copilot/` | `~/.copilot/` | Copilot instructions, skills, agents, settings, and command-line MCP |
| `AppData/`, `Library/` | VS Code profile | Same files, one folder per operating system; the wrong one is excluded by `.chezmoiignore` |
| `dot_bashrc`, `dot_zshrc.tmpl`, `dot_bash_profile` | `~/.bashrc` etc. | Shells |

Neither shared location could be a folder named `shared/`:

- `.chezmoitemplates/` is a **reserved chezmoi name**. `includeTemplate` resolves only
  there, so renaming it breaks every shared rule.
- `dot_agents/` must be named for its target, because `~/.agents/skills` is the
  harness-agnostic path Codex and Copilot actually scan. Claude's per-skill links point
  back to this tree while leaving room for Claude-only skills in `dot_claude/skills/`.

## Where the shared text goes

```
.chezmoitemplates/core.md          -> ~/.claude/CLAUDE.md      (inlined)
                                   -> ~/.codex/AGENTS.md       (verbatim, no frontmatter)
                                   -> ~/.copilot/instructions/core-principles.instructions.md

.chezmoitemplates/rules/<name>.md  -> ~/.claude/rules/<name>.md                     (paths:)
                                   -> ~/.copilot/instructions/<name>.instructions.md (applyTo:)
```

`.chezmoidata.yaml` holds each rule's glob once, so the two wrappers cannot disagree.

Codex is absent from the rules row on purpose: it has no path-scoping, so per-language
rules would be always-on against its 32 KiB budget.

## Before you edit anything here

- Editing a **target** (`~/.claude/CLAUDE.md`) changes nothing durable — it is regenerated.
- Editing a **source** (anything here) does nothing until `chezmoi apply`.
- `chezmoi add` takes a *target* path, never a path inside this directory.
- Filenames carry meaning: `empty_`, `literal_`, `create_`, `symlink_` are attributes, not
  part of the name. See the workflow guide before renaming files.
